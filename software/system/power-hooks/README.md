# Power Hooks

> **Profiles:** `[laptop]`
> **Platforms:** ubuntu-24.04 (primary), Razer Blade 14 hardware

AC/battery transition scripts for the Razer Blade 14, applying battery-aware EPP, platform profile, and backlight settings. These are the user-installed pieces that complement TLP (which handles the TLP-config side).

Mechanism: a single udev rule on `power_supply` events runs `/usr/local/bin/ac-profile` or `/usr/local/bin/battery-profile` whenever the AC adapter is connected or disconnected.

This directory exists so the scripts survive a machine rebuild — they live outside any Debian package and would otherwise be lost on reinstall.

## Files

| Canonical path in repo | Install path | Purpose |
|---|---|---|
| `canonical/usr/local/bin/ac-profile` | `/usr/local/bin/ac-profile` | Run on AC connect: EPP=`balance_performance`, platform=`balanced`, backlight=153/255 (~60%) |
| `canonical/usr/local/bin/battery-profile` | `/usr/local/bin/battery-profile` | Run on AC disconnect: EPP=`balance_power`, platform=`low-power`, backlight=56/255 (~22%) |
| `canonical/etc/udev/rules.d/99-power-profile.rules` | `/etc/udev/rules.d/99-power-profile.rules` | udev rule that invokes the above scripts on `power_supply` change events |

`platform_profile` writes are guarded with `[ -w … ]` because the file does not exist on this firmware (AMD Modern Standby) — the write would otherwise emit a "Permission denied" line on every transition.

## Install (on a fresh machine)

```bash
sudo install -o root -g root -m 0755 canonical/usr/local/bin/ac-profile      /usr/local/bin/ac-profile
sudo install -o root -g root -m 0755 canonical/usr/local/bin/battery-profile /usr/local/bin/battery-profile
sudo install -o root -g root -m 0644 canonical/etc/udev/rules.d/99-power-profile.rules /etc/udev/rules.d/99-power-profile.rules
sudo udevadm control --reload-rules
```

To apply immediately without waiting for a transition:

```bash
sudo /usr/local/bin/battery-profile   # if on battery
# or
sudo /usr/local/bin/ac-profile        # if on AC
```

## Verify

```bash
# Watch a real transition (unplug, then check):
journalctl -t systemd-udevd --since "1 minute ago" | grep profile
cat /sys/class/backlight/amdgpu_bl1/brightness   # should match the profile
cat /sys/devices/system/cpu/cpu0/cpufreq/energy_performance_preference
```

## Related but not in this directory

Three further system changes from the `razer-battery-opt` analysis (2026-06-05) have no file artifact in the repo — they're systemctl state changes. They survive reboot but **not** a reinstall, so they're documented here:

- **`gpu-manager.service` is masked.** Stops the autogenerated `/usr/share/X11/xorg.conf.d/11-nvidia-offload.conf` from being rewritten, which lets the RTX 4070 Mobile dGPU runtime-suspend (~4W). CUDA is unaffected (separate kernel device path).
  - Apply: `sudo systemctl mask gpu-manager.service && sudo rm -f /usr/share/X11/xorg.conf.d/11-nvidia-offload.conf` — then logout/login (Xorg needs to restart for the unbind).
  - Rollback: `sudo systemctl unmask gpu-manager.service && sudo prime-select on-demand`, logout/login.

- **`nvidia-persistenced.service` is masked.** It was running with `--no-persistence-mode` (a no-op state) and would otherwise periodically wake the suspended dGPU.
  - Apply: `sudo systemctl mask nvidia-persistenced.service` (the unit is `static` so `disable` doesn't apply; `mask` is the correct durable disable).
  - Rollback: `sudo systemctl unmask nvidia-persistenced.service`.

- **Refresh-rate drop on battery** was scoped for these scripts but **not applied**. GNOME/Mutter manages display state via `~/.config/monitors.xml` and silently overrides `xrandr --rate` calls, so the planned hook would have no effect. The CEO can drop to 60Hz manually via Settings → Displays when on battery, or a follow-up session can add a Mutter-aware mechanism (`gnome-randr`, D-Bus to `org.gnome.Mutter.DisplayConfig`, or programmatic `monitors.xml` edits with a SIGUSR1 to mutter).

## Backlight tuning

The 56 (~22%) battery / 153 (~60%) AC values are starting points from the analysis. Edit either script to adjust; values are 0–255 on the `amdgpu_bl1` backlight. The CEO can also override live via the keyboard brightness keys — the next AC/battery transition will reapply.

## Rollback (everything in this directory)

```bash
sudo rm /usr/local/bin/ac-profile /usr/local/bin/battery-profile
sudo rm /etc/udev/rules.d/99-power-profile.rules
sudo udevadm control --reload-rules
```

This removes the profile-switching mechanism entirely. TLP continues to manage CPU/PCIe/etc on its own.
